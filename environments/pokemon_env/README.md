# pokemon-env

Pokémon FireRed (US v1.0) as a verifiers v1 environment, played through text only.
The real game runs headless in mGBA; every observation is read from the game's
memory and rendered as text. There are no screenshots and no vision model.

- **Task:** one episode from a start state; the model replies with
  `<buttons>up up a</buttons>` each turn.
- **Reward:** story milestones reached / 42 (towns, routes, gyms, the 8 badges,
  Elite Four). Metrics: `milestones`, `badges`, `malformed_replies`,
  `emulated_frames`.
- **Turn:** the buttons are pressed, then the game runs until it waits for input
  again (dialogue, a menu, the player's control back). One turn never ends
  mid-cutscene or mid-animation.

## What the model sees

```
Turn 14 of 1000.
=== LAST ACTION ===
Pressed a; moved (7, 8) → (7, 8).

=== STATUS ===
Step 14 | Mode: battle | Location: Pallet Town Professor Oaks Lab | Position: (7,8) facing up
Badges: none | Money: ¥3000
Party 1: BULBASAUR Lv5 HP 20/20 OK [Grass/Poison] moves: TACKLE 35PP, GROWL 40PP

=== BATTLE (trainer) ===
Opponent: CHARMANDER Lv5 HP 100% OK [Fire]
Your active: BULBASAUR Lv5 HP 20/20 OK moves: TACKLE 35PP, GROWL 40PP

=== MESSAGES SINCE YOUR LAST ACTION ===
Foe CHARMANDER used SCRATCH!

=== SCREEN TEXT ===
What will
BULBASAUR do?
FIGHT    BAG
POKéMON  RUN
▶ cursor on: FIGHT
```

In the overworld, a map of the current area (one cell per step) follows. Doors
are labeled by where they lead, and a points-of-interest list gives the offset
to each door and exit and how to use it ("step on it, then press down").

Screen text is decoded from the game's own text windows by matching their
pixels against the ROM's fonts, so every dialogue, menu, shop and battle menu
comes out as exact text. Addresses come from the pret/pokefirered
decompilation (`pokemon_env/firered/data.json`, regenerated by
`python -m pokemon_env.firered.gen_data <pokefirered checkout>`).

## Setup (Mila)

1. **Your ROM:** a Pokémon FireRed US v1.0 ROM (`BPRE`, rev 0, sha1
   `41cb23d8dccc8ebd7c649cd8fbb58eeace6e2fdc`). It is not included. Set
   `POKEMON_FIRERED_ROM`.
2. **mGBA bindings:** build them into a directory you put on `PYTHONPATH`. The
   PyPI wheels lack libmgba itself, and are tagged for Python ≤ 3.11 only.
   ```bash
   sbatch -p main-cpu -c 8 --mem=16G -t 1:00:00 --wrap "bash environments/pokemon_env/scripts/build_libmgba.sh"
   # -> $SCRATCH/pokemon/py-mgba ; check with the prime-rl venv:
   PYTHONPATH=$SCRATCH/pokemon/py-mgba .venv/bin/python -c "import mgba.core"
   ```
3. **Start state** (once, about 5 s): plays the intro and saves the game in the
   player's bedroom. It uses the default names, text speed FAST and battle
   animations OFF.
   ```bash
   PYTHONPATH=environments/pokemon_env:$SCRATCH/pokemon/py-mgba .venv/bin/python \
     -m pokemon_env.make_start_state --out $SCRATCH/pokemon/firered_start.state
   export POKEMON_FIRERED_STATE=$SCRATCH/pokemon/firered_start.state
   ```
   `start_state` can also be a directory of `*.state` files, which tasks use
   round-robin. Tasks sharing a state still differ: task *i* idles
   `i % rng_frames` frames first, which shifts the game's RNG.

## Run

```bash
sbatch scripts/pokemon/eval.sbatch                 # Qwen3.5-9B, r50-1 eviction, 64 episodes x 1000 turns
KEEP=full MODEL=Qwen/Qwen3.5-4B sbatch scripts/pokemon/eval.sbatch
```

Results go under `$SCRATCH/kv-race/pokemon_eval/<cell>/<job>/`: `episodes.jsonl`
holds one line per episode (milestones and the turn each was reached, party,
buttons, trace tokens), and `summary.txt`.

Taskset knobs: `info_level` (raw / semantic / oracle), `view` (full / local,
`radius`), `max_buttons`. Env knobs: `max_episode_steps`, `settle_max`,
`episode_log`.

## Tests

```bash
POKEMON_FIRERED_ROM=... POKEMON_FIRERED_STATE=... \
  PYTHONPATH=environments/pokemon_env:deps/verifiers:$SCRATCH/pokemon/py-mgba .venv/bin/python -m pytest environments/pokemon_env/tests
```

## Throughput

On one Mila CPU node, an env without a model runs ~39 steps/s per core, and 32
in parallel reach ~866 steps/s. The model is the bottleneck.

## Known gaps

- The naming-keyboard cursor is a sprite and isn't reported. The prompt tells
  the model to press start then a.
- Some menu graphics can leak into the screen text as stray glyphs (e.g. the
  "HP" label on the party screen). Exact numbers are always in STATUS / BATTLE.
